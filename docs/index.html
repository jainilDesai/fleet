A pixel office for your Claude Code team.

You talk to one agent, the CTO. It plans the work, hands tasks to the rest of the team, and you watch all of it happen. Every agent is a real Claude Code session on your Mac.

$npm install -g @jainil_desai/fleet
Read the docs GitHub

Then run fleet in a git repo. Free and open source (MIT). macOS, Node 20+, Claude Code and tmux.

How it works

You talk to the CTO. The CTO runs the team.

The CTO breaks your request into tasks and assigns them. Each agent starts only when it's first needed.

You

Ask for a feature, a fix or a deploy.

→

CTO

Plans the flow, creates and assigns tasks. Never writes app code or deploys.

→
  • PlannerTurns the request into a plan.
  • ImplementerBuilds the approved plan and commits.
  • QAInstalls, tests, reports with evidence.
  • ReviewerReviews the diff for bugs and simplicity.
  • DeployerDeploys only when you asked and approved.

See every agent at its desk

Each agent shows what it's doing now: working, idle, waiting on you, or in review. Tasks move across the plan wall as agents report back.

Click an agent to open its drawer: its task and branch, and every message between you, the CTO and that agent, rendered as Markdown.

You decide, in one list

Questions, plan and deploy approvals, and Claude Code permission prompts all land in Actions. A permission prompt shows the full command; Allow or Deny it from the browser or answer in the terminal.

Nothing is ever allowed automatically, and a production deploy is labelled so it never looks routine.

Make it your flow

Every agent, the CTO included, has a role you can rewrite in Settings → Team or load from a Markdown file. Attach skills by pasting a SKILL.md or uploading one.

Save your own defaults as ~/.fleet/roles/<role>.md and every new repo's team starts from them.

Real sessions, not a simulation

Each agent is claude running in tmux, in its own git worktree on its own branch. Your own checkout is never touched.

Open in terminal attaches iTerm or Terminal.app to any agent so you can read or type into the real session. Agents keep running if you close Fleet.

$ tmux attach -t fleet-my-app-implementer

worktree ~/.fleet/projects/my-app/implementer

branch   fleet/my-app/implementer

Pull requests that move the plan

With the GitHub CLI (gh) signed in, Fleet follows the team's pull requests and links each one to its task and agent.

  • Review comments go back to the author.
  • A passed review goes to the CTO.
  • A merge marks the task done.

PRs from forks are ignored.

review comment → author

review passed → CTO

merged → task done

Get started

Needs

  • macOSiTerm optional; Terminal.app works.
  • Node 20+No runtime dependencies.
  • Claude Codeclaude, signed in.
  • tmuxPlus gh, optional, for PRs.
  1. Install tmux and Fleet.
    brew install tmux
npm install -g @jainil_desai/fleet
  2. Start it in any git repo, or point it at one. Your browser opens http://localhost:7788.
    cd ~/code/my-app && fleet
fleet --repo ~/code/my-app
  3. Optional: start Fleet at login for this repo, in the background. Run it in each repo you want; fleet --list shows them all.
    fleet --autostart

Options, customising roles and how it all works are in the docs.
