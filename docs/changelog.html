Changelog

Every release of Fleet. Update with npm install -g @jainil_desai/fleet@latest.

0.10.1

18 November 2026
  • Every answer to you shows in the agent's chat: questions you type in an agent's terminal show there too, and an answer is no longer lost when a teammate's message arrives at the same time.
  • Agents' questions get proper selectors: pick one or several options (each with its description) or write your own, at the top of Action items.

0.10.0

18 November 2026
  • A team of its own for New work: a new CTO on its own page and port, only that work's tasks, its own card on the home page. It starts alone and adds or removes agents as it needs them.
  • Agents' questions in Action items: pick an option and the answer goes straight back to the agent.
  • Long messages arrive whole, tasks can't get each other's results, and the CTO's chat shows your conversation with team traffic one click away.
  • Agents can run the tests: shared node_modules and copies of your env files in every worktree. Done asks first when work is unfinished.

0.9.0

17 November 2026
  • Refresh with a handoff: ⟳ in every agent's chat swaps in a fresh session that starts from a handoff of what the old one did. Automatic once context passes 60%.
  • Done boards move to History: their agents hand off and stop, extra agents are removed, worktrees are deleted (Fleet asks first about uncommitted work), and Reopen brings a board back.

0.8.1

16 November 2026
  • A fresh CTO for each New work: a clean session (on by default), started with Fleet's current plan. The same plan comes back after a context compaction, so the CTO works from facts, not memory.

0.8.0

16 November 2026
  • + New project on the home page: start Fleet on any folder (path suggestions or the folder picker), with an optional first task. Fleet can set up git for a folder that isn't a repo yet, if you tick the box.
  • New work is easier to follow: the wall shows the newest board, Boards opens on it, and a started board links to the CTO's replies.

0.7.0

16 November 2026
  • New work. Boards → + New work (or New work on the home page) sends a prompt to the CTO on its own board: investigation only or build, the current team or extra agents per role (each in its own worktree), now or saved for later.
  • The CTO can ask for agents with the new add_agent tool. You approve each one in Action items.
  • The top bar's plan wall picker now reads Wall shows: it only changes the view.

0.6.1

16 November 2026
  • The Fleet logo in a project's top bar now opens the home page; the separate Home button is gone.
  • Stop team moved from the top bar to Settings → Team.
  • Stop idle agents. Settings → Workflow: Fleet stops an agent that has sat idle for 1, 3 (default) or 7 days, or never. It skips agents that are working, waiting on you, have an open Action item or unsent text. An idle agent does nothing on its own, but waking it days later re-sends a long, uncached context; the next start is a fresh session with its role and task.

0.6.0

15 November 2026
  • Home page. http://localhost:7788 is now Fleet's home: every project with its status, agents, who needs you and its API-equivalent cost, with Open, Start and Stop. Type fleet outside a repo, fleet home or fleet open to get there; every project's top bar links back to it. Projects now run on ports from 7789; an existing login item on 7788 moves by itself, and running agents keep working.
  • Install as an app. In Chrome or Edge, install the home page from the address bar; in Safari, File → Add to Dock. Then open Fleet from the Dock or Spotlight.
  • Stop team. One button stops every agent, or stops them and quits Fleet.
  • Role picker. The Role field is a real menu: built-in roles, your saved roles and New role…. Save as my role keeps a role's prompt and skills in ~/.fleet/roles, so the next agent with that role, in any project, starts with them.

0.5.0

15 November 2026
  • Linux. Install tmux (sudo apt install tmux), then the same npm install -g and fleet. The browser opens with xdg-open, Open in terminal uses your terminal app (gnome-terminal, konsole, kitty, xterm and others), and banners use notify-send.
  • Windows through WSL. Fleet runs inside WSL and opens in your Windows browser; Open in terminal opens a Windows Terminal tab. On Windows without WSL, fleet explains how to set it up.
  • Start at login on Linux and WSL uses a systemd user service, with --stop, --start, --no-autostart and --all working as on macOS.
  • Setup checks show the terminal and the install commands for your platform. macOS is unchanged.

0.4.0

15 November 2026
  • Several projects at once. Run fleet in each repo: a second copy takes the next free port, fleet --list shows them all, and the ⇄ switcher in the top bar jumps between them. Each repo gets its own team, even two repos with the same folder name.
  • Two teams on one repo. New agent branches are named fleet/<project>/<agent>, so two checkouts of the same repo can each run a team.
  • Start at login per repo. fleet --autostart makes one login item per repo; --stop, --start and --no-autostart act on this repo only (--all for every one). Older login items keep working.
  • Setup checks in the app. The welcome screen and Settings → Project show tmux, Claude Code and its sign-in, gh, the GitHub remote and your terminal, each with the command that fixes it. With no remote or gh, agents commit on branches and don't push.
  • Trust folder. Answer Claude Code's first-start folder-trust prompt from Action items or the agent's drawer.
  • Open in terminal. iTerm is optional: Terminal.app works now (it didn't before). If macOS blocks it, Fleet shows the tmux attach command to run yourself.
  • Clear messages for a repo with no commits, a bad --port and unknown options; fleet --version. Only one copy raises banners. No more errors on a Mac where Claude Code never ran. A permission prompt counts once.

0.3.2

15 November 2026
  • Plan and deploy approvals now have Approve / Reject buttons. Rejecting tells the agent to stop, not to find another way.

0.3.1

  • The top bar fits at every window width. Below 1536px it hides the repo path and the "Plan wall" label, so the project name always shows (hover it for the repo).

0.3.0

14 November 2026

Fleet is now an office for a team of Claude Code agents, built on JSM HQ by JavaScript Mastery (MIT).

  • Pixel office. HQ's office UI replaces the old dashboard. Each agent sits at a desk and shows what it's doing; tasks move on the plan wall; messages are rendered as Markdown.
  • A CTO-led team. You talk to the CTO, which plans and assigns work to a Planner, Implementer, QA, Reviewer and Deployer. Agents start the first time they're needed.
  • Real sessions. Every agent is claude in tmux, in its own git worktree under ~/.fleet/projects/<repo>/. Open in iTerm attaches to it.
  • Actions. Questions, plan and deploy approvals, and Claude Code permission prompts (Allow/Deny) in one list.
  • Make it your flow. Every agent, the CTO included, has an editable role you can load from a file, and its own skills you can paste or upload. ~/.fleet/roles/<role>.md sets your own defaults for every new repo.
  • Pull requests. With gh, Fleet follows the team's PRs: review comments go to the author, passed reviews to the CTO, merges close the task. PRs from forks are ignored.
  • Breaking: Fleet now needs tmux and works on one git repo per run: the current folder or --repo <path>.
  • Breaking: the Agents, History, Usage, MCP and Plugins pages are gone. macOS banners still work, and history is still recorded.
  • Auto-start now remembers the repo. If you set it up before 0.3.0, run fleet --autostart again from your repo.

0.1.0

10 October 2026

First public release.

  • Agents: every live Claude Code session on your Mac, grouped by repo, with status, model, branch, current tool call, cost including subagents, and context use. Each session's panel shows its subagent tree and workflow phases.
  • History: a record of every session (title, project, branch, model, cost, prompts, files edited) that stays after Claude Code deletes the transcript, with search and saved summaries.
  • Notifications: inbox, tab count and macOS banners when an agent needs you, finishes, or a subagent or workflow ends. With terminal-notifier installed, a banner opens the session's terminal tab when clicked.
  • New agent: starts claude in Terminal or iTerm through your login shell, with model, effort, permission mode, name, first prompt and an optional worktree.
  • Usage, MCP servers, plugins and skills, and plan limits through the statusline.
  • The Agents page warns when it can't read Claude Code's transcript format, instead of showing zeros.
  • Workflow journal files are no longer shown or counted as agents.
